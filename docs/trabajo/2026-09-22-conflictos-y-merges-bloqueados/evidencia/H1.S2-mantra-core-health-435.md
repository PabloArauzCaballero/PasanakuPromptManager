## Qué había en cada lado

`ContentDialog`. Los dos lados agregaron inputs **distintos** en el mismo punto.
La base no tenía ninguno de los dos:

    echo "$k -> base:$(git show :1:$F|grep -c $k) rama:$(git show :2:$F|grep -c $k) dev:$(git show :3:$F|grep -c $k)"

- **rama**: `closeGuard`, que se consulta dentro de `close()`.
- **dev**: `size`, `dismissible` y la salida `dismissAttempt`, que se consultan
  en `solicitarCierre()`.

## Criterio de la resolución

Se conservaron **los dos**. No se pisan: el resto del archivo automezcló ambos
mecanismos de forma coherente y se verificó leyéndolo:

```text
protected solicitarCierre(): void {
  if (!this.dismissible()) {      // ← de dev
    this.dismissAttempt.emit();
    return;
  }
  this.close();
}

close(force = false): void {
  ...
  const guard = this.closeGuard();   // ← de la rama
  if (force || guard === null) { this.doClose(); return; }
  ...
}
```

`dismissible=false` delega en quien hospeda el modal; `dismissible=true` deja que
`closeGuard` pregunte en línea. Se apilan sin contradecirse.

**Anotado, no arreglado:** son dos formas de proteger lo no guardado y convendría
unificarlas. Eso es un refactor y queda fuera del alcance de resolver un conflicto
(regla 00 §3.2). Se deja registrado para quien revise el PR.
